# compositor plugin: code conventions

- Node ≥ 22, ESM (`.mjs`), no build step, no TypeScript. Scripts live under `plugin/scripts/<area>/`.
- Shared helpers in `plugin/scripts/lib/`: `args.mjs` (`parseArgs`, `fail`, `list`), `fs.mjs` (`readJson`, `writeJson`, `writeText`, `ensureDir`, `walk`, `slugify`), `browser.mjs` (`launchBrowser`, `findChromium`, `loadPuppeteer`, `loadSharp`, `CHROMIUM_ARGS`), `ffmpeg.mjs` (`ffmpeg`, `probe`, `loudness`, `loudnormFilter`, `pngSequenceInfo`), `color.mjs` (`normalizeColor`, `hexOf`, `contrast`, `deltaE`, `hexesIn`, `luminance`), `svg.mjs` (`el`, `svg`, `pathFromPoints`, `smoothClosedPath`, `rng`, `bbox`, `centroid`, `n`), `hyperframes.mjs` (`hf`, `render`, `snapshot`, `check`, `lint`, `tts`, `transcribe`). Use them; do not duplicate.
- Dependencies available: `culori`, `d3-delaunay`, `polyclip-ts`, `opentype.js`, `yaml` (in `plugin/package.json`), plus `sharp` and `puppeteer-core` through `lib/browser.mjs` (resolved from the global hyperframes install). Add nothing else without a note in the module header explaining why.
- Every CLI: `parseArgs(process.argv.slice(2))`, `--json` prints one JSON object to stdout, human summary otherwise; exit 0 pass, 1 fail, 2 usage/schema error. Scripts never prompt.
- Every module exports its functions so tests and other scripts import them; the CLI entry is guarded by `if (import.meta.url === \`file://${process.argv[1]}\`)`.
- Determinism: no `Date.now`, no unseeded random, no network inside gates or generators. Fonts and scripts are local files.
- Tests: `plugin/tests/<area>.test.mjs` with `node:test` + `node:assert/strict`; fixtures under `plugin/tests/fixtures/`; run with `node --test 'tests/**/*.test.mjs'` from `plugin/`. Tests must not need the network or a browser unless the test name says `[browser]`.
- Gates: common `check`, `offline`, `palette`, `seams` (+ `probe`, `loudness` at dist); per mode `social-lint`, `ad-lint`, `promo-lint`, `guide-lint`, `explain-lint`, `logo-gate`. An all-skip report exits 1: nothing measured is not a pass.
- Gate interface: a gate module exports `async function run(ctx)` → `{ gate, status: "pass" | "fail" | "warn" | "skip", findings: [{ rule, status, evidence, hint }] }` where `ctx = { runDir, stage: "proof" | "dist", plan, brand, targets }`. `plan` is `runDir/plan.json`, `brand` is the resolved brand.json object. A gate fails only on rules it can measure; it skips with a reason otherwise. Hints come from `plugin/references/gates.md`.
- Run directory layout (inside the product repo): `compositor/runs/<slug>/{brief.md, plan.json, project/, proof/, dist/<target>/, gates.json, findings.md, run.json}`. `compositor/brand.json` and `compositor/fonts/` sit beside `runs/`.
- plan.json shape: `{ mode, slug, title, targets: ["ig-square", …], compositions: [{ file: "project/ig-square.html", target, width, height, duration, fps, kind }], copy: { headline, body, cta, legal }, scenes: [{ id, start, duration, route, carrier }], audio: { vo: "project/assets/vo.wav" | null, music: null, captions: "project/assets/captions.json" | null, language }, steps: [...] (guide), mark: {...} (mark), eval: { row } }`.
- Comments: only constraints the code cannot show. Delete dead code. Minimal interfaces, substantial implementations.
- Do not commit. The orchestrating session commits.
